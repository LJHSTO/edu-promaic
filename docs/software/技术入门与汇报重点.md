# 技术入门与汇报重点

先把一次操作想清楚：浏览器接收动作，API 找到会话，Agent 决定如何帮助，模型和工具处理知识，数据库记住过程，基础设施让服务持续运行。完整方案见 [architecture.md](architecture.md)。

## 必讲 A：系统的六层

| 层次 | 技术 | 用一句话讲清楚 |
|---|---|---|
| 界面 | React + TypeScript + Vite | 把课程、图形和助手做成可复用组件，组织学生与教师工作台。 |
| 接口 | NestJS / Node.js | 接收请求、检查身份和参数，把会话交给对应学习服务。 |
| Agent | LangGraph JS | 用状态图安排检索、工具和反馈，学生回来后可以继续。 |
| 模型 | DeepSeek + BGE-M3 | 前者组织解释，后者把查询和材料转为可比较的向量。 |
| 数据 | PostgreSQL + pgvector | 保存课程、学习记录、状态和知识向量。 |
| 运行 | Docker Compose + Nginx + Actions + Sentry | 启动服务、提供 HTTPS、检查改动和定位故障。 |

**可以这样讲：**用户操作先进入前端，经 API 找到会话，再由 Agent 组织模型与工具，结果和状态写回数据库；部署与检查工具支撑整个过程。

## 从 0 理解网页与前端框架

HTML 定义页面结构，CSS 定义外观，JavaScript 响应点击。React 把它们组织成组件：例如帮助面板接收提示和来源，显示不同状态。TypeScript 在开发时检查数据类型，减少把错误字段传给组件的问题。Vite 提供开发预览和构建。它们不会自动产生智能，智能来自后面的服务。

React Router 决定当前页面；TanStack Query 管理从服务器取得的课程与会话，处理缓存和重新请求。课程内的小开关由 React 状态管理。现有课件通过 iframe 接进活动容器，用约定的 postMessage 消息传递操作，之后再逐步组件化。

KaTeX 渲染公式，SVG/Canvas 画二维活动，Three.js 画三维场景。它们负责呈现与交互，不负责决定帮助策略。

## 从 0 理解接口、服务与存储

HTTP 是浏览器与服务端通信的规则，JSON 是双方交换数据的格式。Node.js 在服务器执行 JavaScript；NestJS 把服务分成课程、会话、评价等模块。SSE 是服务端持续发送状态和文字的通道，适合逐步显示帮助。

PostgreSQL 是关系数据库。一张 learning_sessions 表记录当前阶段，一张 learning_events 表记录发生过哪些操作；事务把“更新状态”和“写事件”作为一次整体操作。唯一 eventId 防止网络重试把同一事件存三次。revision 防止旧页面覆盖新状态。

JSONB 存储图形参数等结构灵活的数据；pgvector 是 PostgreSQL 的扩展，保存向量并比较相似度。二者不是两个独立数据库。

## 必讲 B：RAG 怎样把课程带给模型

模型不天然知道我们的当前讲义。RAG 先在课程材料中找相关片段，再让模型结合片段回答。材料先按定义、条件和例题切分，保留版本、章节与页码；BGE-M3 把片段编码成 1024 个数。提问用同样的模型编码，pgvector 找相近片段；关键词召回补足符号与专有术语，再用 RRF 合并排序。

**可以这样讲：**我们的帮助依据当前课程。检索后过滤版本和用途，材料不够才补查；提示附有能展开核对的出处。

关键词检索不等于向量检索，知识图谱也不等于向量库。前者匹配词项，向量检索匹配语义，图谱记录概念关系。中文全文检索需要预先分词，默认英文词典不能直接解决中文分词。

## 必讲 C：Agent 和两个循环

RAG 是获取依据的方法，Agent 是推进任务的执行流程。Agent 读取目标、活动状态和偏好，选择行动，再看结果。LangGraph 把这些步骤写成节点和分支，并保存检查点。

内层循环：检索 → 检查材料 → 必要时补查 → 调工具 → 核对结果 → 给出一步帮助。外层循环：等学生操作 → 更新学习状态 → 决定继续、换解释或进入独立检查。

**可以这样讲：**内层完成一次帮助，外层跟随一段学习。等待学生时程序保存状态，不会一直让模型反复运行。

工具调用是“模型提出工具名与参数，程序实际执行”。例如 evaluate_values 接收已登记函数和采样点，返回数值表。模型不能自己声称工具已经运行，也不负责修改标准答案。

## 必讲 D：主动学习的特点

六维偏好围绕判断依据、介入时机、支持起点、显示位置、控制方式和帮助后继续。它们让主动帮助与学生当时的任务协调起来。触发不能只看停留时长，也要结合当前作答、操作、已接受帮助与学生选择。

**可以这样讲：**系统先判断现在是否需要帮助，再按学生偏好给出邀请或线索；最后用新的独立任务看学生能否继续，而不是只记录聊天有没有完成。

## 必讲 E：怎样扩展到其他学科

通用核心负责会话、偏好、Agent、过程记录和教师工作流。学科包提供概念、教材片段、活动、题目、评价量规和专业工具。微积分换成物理时，图形活动可换成仿真，数值工具增加单位检查；编程学科增加受隔离的代码测试工具。

**可以这样讲：**换课程时主要更换知识与活动，学习流程和帮助机制继续复用。

## 答疑备用：部署、测试和模型选型

Docker 把运行依赖装进可复用环境，Compose 启动应用与数据库，Nginx 处理外部 HTTPS 入口。GitHub Actions 在提交时检查代码，Playwright 像用户一样点击界面，Sentry 收集运行错误。它们分别解决交付、验收和故障定位问题。

为什么不用 Next.js？这是登录后的学习工作台，主要需要客户端活动与已有 API，React + Vite 迁移范围更直接。为什么不用多个 Agent？当前任务由一个有状态编排器配合工具即可完成。为什么选 PostgreSQL？课程、会话和作答适合关系事务，pgvector 又能把课程检索放在同一数据系统。

模型供应商、前端框架和数据库是不同层的选择。更换生成模型不应重写界面；更换向量编码模型则需要重建索引。技术方案是目标设计，可运行演示的真实依赖以仓库 package.json 为准。
