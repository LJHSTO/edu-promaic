# 非功能需求规格说明书

版本：0.2；修订日期：2026-10-13；对应议题：[#6](https://github.com/LJHSTO/edu-promaic/issues/6)。

质量目标按 URPS（可用性、可靠性、性能、支持性）组织，覆盖交互、数据和教学内容。各项目标及验证方式如下。

## 1. 环境与测试口径

- 当前演示：Node.js 22 及以上，现代 Chrome / Edge 浏览器；Windows、Linux 由 CI 执行检查。其他浏览器须另做兼容验证。
- 性能目标的基准环境为 4 核 CPU、8 GiB 内存、单个 Node.js 进程和本地网络。使用内置决策，预热 100 次后测量 1,000 次，记录环境、原始耗时和 P50 / P95 / P99。
- 并发目标：30 个虚拟学生各每 5 秒提交一次，持续 10 分钟；扩展到 200 人前另做容量评估。
- 提示安全和课堂试用须有教师审核与参与同意；自动化测试只能验证确定性的流程约束。

## 2. 需求与验收

| 编号 | 属性 | 明确要求 | 验证方法 | 当前状态 |
|---|---|---|---|---|
| NFR-1 | 可用性：上手 | 用户无需安装插件，打开本地服务即可完成练习和验证。试用时至少 8/10 名首次用户在 5 分钟内完成流程，不依赖开发者代操作 | 记录任务完成时间、失败原因及样本招募条件 | 流程可演示；新用户测试待进行 |
| NFR-2 | 可用性：低打扰 | 提示不使用阻塞弹窗、不主动抢焦点；可收起和关闭。320 px 及以上视口无横向滚动；键盘可完成主要操作 | 桌面与窄屏走查、Tab 操作、焦点检查 | 浏览器检查 |
| NFR-3 | 可靠性：失败反馈 | 决策请求 3 秒超时，显示中文说明并保留已选答案；按钮恢复可用。同一次失败提交不重复增加错误数 | 模拟超时、断网、非 JSON 返回及 HTTP 500 | 实现与异常检查 |
| NFR-4 | 可靠性：恢复 | 刷新或断网重传时恢复当前题目、已确认提交及保护阶段。维护窗口可校验备份并恢复课堂数据 | 重启、版本冲突、重复事件，以及从备份恢复会话与审计 | 接口、浏览器及密文备份恢复通过测试；目标环境记录恢复用时和数据恢复点 |
| NFR-5 | 安全与隐私 | 学生仅访问本人会话，教师和审计员仅访问各自授权的班级及数据类别 | 分别检查角色、跨学生与跨班级访问 | 受保护配置测试通过，真实机构接入见[安全与部署](../software/security.md) |
| NFR-6 | 安全与隐私 | 采集作答事件和结构化运行回执。试用学习记录拟保存 30 天，审计记录按适用要求留存 | 字段白名单、到期清理、导出和重启复查 | 支持机构配置会话期限。已验证清理不会把过期会话带入教师汇总，也不会被在途回复重新写入 |
| NFR-7 | 支持性：可追踪 | 保存会话、阶段、事件顺序及线索来源、工具和执行结果 | 模拟写入或审核失败，核对记录和顺序 | 事件及提示同次提交，失败不变更已接受状态 |
| NFR-8 | 提示范围 | 保护阶段与关闭提示期间，自动提示和主动求助均为 L0。固定提示经人工审核，内容限于下一步线索，禁止给出原题结果或完整解法 | 组合规则测试、服务端阶段测试及逐模板人工评审 | 已验证关闭提示、独立作答与迟到线索的服务端约束，教师评审待进行 |
| NFR-9 | 性能：计算 | 基准环境中单次纯规则决策 P95 ≤ 10 ms | 使用高精度计时，固定输入批次，记录样本数与分位数 | Linux 4 核、8 GiB 进程内测得 P95 0.001012 ms，1,000 次。[性能报告](../software/code_quality.md#决策接口性能) |
| NFR-10 | 性能：服务 | 30 用户负载下，决策接口 P95 ≤ 200 ms，非预期 5xx 比例 < 1%。分别记录请求延迟和纯规则耗时 | 负载测试报告，统计状态码与延迟 | Linux 参考环境中的回环接口实测 10 分钟，P95 20.332 ms，非预期 5xx 为 0/3,600。[性能报告](../software/code_quality.md#决策接口性能) |
| NFR-11 | 支持性：可维护 | 决策规则独立于网络、文件和浏览器。变更教学阈值时校验参数，新增题目沿用现有沉默规则 | 模块依赖走查、参数测试、课包和题目加载测试 | 已验证规则阈值和课程包的版本、题目、概念及发布状态 |
| NFR-12 | 支持性：可测试 | 默认测试命令覆盖单元与集成；每条保护规则、阈值边界和组合优先级有案例；CI 在 Node.js 22、24 的 Windows / Linux 环境执行 | 检查测试案例和 Actions 结果；有需要时再测覆盖率 | CI 已配置 |
| NFR-13 | 输入防护 | JSON 请求体最多 16 KiB；类型、范围与 Content-Type 不合法返回明确 4xx，不执行评估；静态路由只开放演示资源 | 非法 JSON、字符串布尔值、负数、超限体与路径访问集成测试 | 已实现 |
| NFR-14 | 可选模型可靠性 | 外部模型只接收公开课程候选和层级；2.2 秒超时或返回无效结果时恢复确定性选材 | 服务故障注入、数据和输出契约检查 | 结构化选材适配器通过模拟响应测试；机构启用前验证实际服务 |

## 3. 结果如何记录

每项验收保留执行日期、环境、样本数、命令或操作步骤、实际结果与限制。测试通过只对应已执行的案例。性能结果注明测量环境和负载，用户满意度、课堂迁移与保持通过后续试用采集。
