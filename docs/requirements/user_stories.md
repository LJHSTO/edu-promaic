# 用户故事与验收场景

修订日期：2026-10-13。需求状态以[功能规格](functional_spec.md)为准，本文用于组织用户能够观察到的行为。

| 故事 | 用户希望做到什么 | 给定条件与操作 | 应当看到什么 | 关联验收 |
|---|---|---|---|---|
| US-01 | 学生卡住时先得到一个小提示 | 在原题连续提交两次错误选项，没有关闭提示 | 第一次只反馈错误；第二次出现 L1 自我解释卡片，选项仍可操作 | AC-01 |
| US-02 | 学生演算时不被停顿提示打断 | 没有连续错误，停顿 100 秒；或正在输入有效步骤 | 不发主动提示；收到沉默原因，不能仅因停顿判为困难 | AC-02 |
| US-03 | 学生能决定要不要继续帮助 | 关闭本题提示后再提交错误；恢复后主动求助 | 关闭时不出现新提示；恢复后可主动取得下一层线索；收起提示不影响答题 | AC-03 |
| US-04 | 学生确认自己能独立做题 | 看过提示后答对原题，点击进入验证 | 出现不同数值的同概念题；旧提示清空，求助控件禁用；错误作答也不提供提示 | AC-04 |
| US-05 | 学生分清首次通过和重试完成 | 验证题第一次答错，第二次答对 | 显示“重试后完成”，不写成首次独立通过或长期掌握 | AC-05 |
| US-06 | 学生网络出错时能继续尝试 | 提交请求超时、返回错误或非 JSON | 显示中文说明，保留选择；重新提交不把失败操作重复累计 | AC-06 |
| US-07 | 教师了解共性误解 | 教师查看所授班级的知识点统计 | 同时看到错误、提示、验证比例及样本量，不用即时正确率代替独立学习证据 | AC-07，后续 |
| US-08 | 教师检查某次提示是否合适 | 教师选择匿名会话回放 | 按顺序看到尝试、规则原因、提示内容版本、学生响应和验证结果，包括沉默决策 | AC-07，后续 |
| US-09 | 教师导出可用且受控的数据 | 授权教师导出所授班级记录 | 仅包含必要匿名字段；跨班级拒绝访问；导出操作有记录 | AC-07，后续 |

这些是设计场景，尚不代表真实用户访谈。当前演示只实现 US-01、03–06；US-02 的有效输入标志由 API 支持，页面没有草稿编辑器。US-07–09 需下一阶段实现。

## 关键保护场景

给定学生已进入验证题，即使请求同时包含 `requestedHelp=true`、10 次错误、L5 历史提示和长停顿，决策仍须为 `SILENCE`、L0，页面无旧提示。后续测试还要覆盖刷新和伪造客户端状态，保护不能只靠按钮禁用。
