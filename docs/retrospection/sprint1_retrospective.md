## 完成了什么

- 按课程要求整理为文档、代码和测试三条目录线，迁移原有问题定义、领域模型、课程与评测内容。
- README 改为运行入口，需求正文进入单独规格文件。安装、同源页面入口和 API 示例与代码一致。
- 统一“连续两次错误后先给 L1”，补上关闭、冷却、预算及保护优先级；变式题清空旧提示，并区分首次验证与重试完成。
- 创建项目看板、里程碑、缺陷优先级标签与中文缺陷表单；向已确认的组员和教师发送协作邀请。
- 用自动化规则与 HTTP 测试检查边界，用浏览器检查提示控制、完整验证、断网、窄屏和键盘操作。具体结果见[落实记录](../mgmt/议题落实记录.md)。

## 发现的问题

原先文档将教师回放、审计写入、KaTeX 和模型接入写成了当前能力，但代码还不支持。静态“tests passing”徽章也不能随测试结果变化。修订后改用真实工作流徽章，并为需求标明实现状态。

原先 README 建议直接打开 HTML，前端却使用相对 API 地址，运行方式不成立。现在页面由同一个 HTTP 服务提供。“极限不存在”的错误选项也有反馈，不再只有一个错误选项计数。

## 还不能下的结论

保护与沉默规则通过测试，只说明这些输入下行为符合约定，不能证明提示时机已经适合真实学生。当前没有课堂反馈、迁移与延迟保持数据，没有性能负载报告，也没有持久化审计或教师端。

下一轮优先确认成员分工和教师内容审核，再实现服务端保护阶段、课程包与事件保存。真实班级数据在权限和隐私方案完成后才接入。
